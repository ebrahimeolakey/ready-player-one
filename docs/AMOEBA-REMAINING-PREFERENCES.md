### 审阅位置控件补查：不是下拉菜单

补查要求是仅展开选项、不选择新值。实际第一次点击 `Breadcrumb` 后，可访问性树立即变成 `Floating island`，没有出现菜单。按 Escape 后设置页关闭；重新打开 General 仍为 `Floating island`，说明 Escape 不会撤销该变化。随后点击该控件一次恢复 `Breadcrumb`，再关闭并重新打开设置，确认仍为 `Breadcrumb`。因此本次发生过一次非预期的临时偏好切换及恢复，不能表述为全过程未改变设置。

直接确认的两个状态名称是 **Breadcrumb** 与 **Floating island**，交互是点击循环切换。未打开会话检查两种布局的效果，也没有操作其他设置。

### 对旧记录的重要纠正

“重置内置提示”不是“重置 Agent 系统提示词”。原版明确指 **恢复被设为“不再询问”的 Code-OSS 警告与提示**。不能实现为修改系统 prompt、协作提示、Provider 指令或项目指令，也不能将这两类功能混称。

原版小地图说明明确写的是 **agent 正在写入的位置**。它没有在本次证据中承诺显示所有人的实时光标、选区、浏览位置或完整协同编辑；这些不能从一句说明扩展为已证实要求。

VS Code 导入入口明确提到扩展，足以证明原版有这个产品入口；**不足以证明任意 VS Code 扩展、Marketplace 安装、扩展宿主 API 或调试适配器均兼容**。

## 后续实现验收建议（本项目设计，非原版已观察行为）

以下条目为可测试的建议，需实现后另行验收；不把推断写成原版规格。

### 1. 审阅控件位置

- 提供页头路径区域与浮动区域两种位置，对应已证实的 `Breadcrumb` / `Floating island`；中文名称准确表达位置。若对齐原版交互，使用点击循环切换而非声称原版有下拉菜单。
- 同一组真实 diff 审阅操作只改变呈现位置，不改变 staged/unstaged 范围、目标文件、权限或提交行为；切换不触发 Git 写操作。
- 在长 diff 滚动、窄窗口、空 diff、只读成员、切换文件/会话后验证控件仍绑定正确上下文，且没有同时出现两套可误操作控件。
- 持久化后重启恢复；不能仅保存一个无视觉效果的设置值就视为完成。

### 2. 聊天编辑器标签

- 首先明确本项目标签对象是会话、成员 Agent 会话还是另一种聊天；原版这项映射仍缺直接观察，不能自行命名后宣称 1:1。
- 在本项目确定映射后，显式打开动作应创建或聚焦同一聊天标签。重复点击不重复标签，不创建新 Provider 会话，不重放历史输入。
- 关闭标签只关闭视图；不自动停止运行、删除记录或丢弃未发送草稿。开关切换、会话切换与重启要有明确的恢复策略，并验证标题/内容/发送目标一致。
- 与文件编辑器共存时保留未保存文件；不能为了显示聊天覆盖编辑器草稿。

### 3. 小地图 Agent 写入位置

- 复用真实文件变更证据，只在已知当前文件、版本及可映射行范围时显示位置。仅有文件路径而没有可靠行范围时，不伪造行号。
- 区分“正在写入”与“最近一次写入”：若只能从完成后的变更计算位置，应据实命名，不能把事后标记宣称为实时输入位置。
- 使用真实成员/Agent 身份关联颜色；关闭协作者颜色后仍能区分标记来源，例如简短名称提示。小地图关闭后不残留标记层。
- 以两个合成协作客户端验证文件切换、版本变化、断开重连、Agent 结束及过期标记的清理；切换工作区或根目录后不得显示旧文件位置。
- 本次没有证据决定原版 Editor 的 minimap 设置和 General 此开关是否共享存储；未来实现应先明确关系，避免两个设置互相矛盾。

### 4. 恢复“不再询问”的警告与提示

- 先列出本项目实际拥有的可持久化“不再询问”项及其存储键；没有对应能力时，应明确尚未提供，不能添加无效 Reset 按钮冒充等价功能。
- 只清除本项目这一类提示的抑制标记，并用合成设置验证重新触发会显示对应提示；不重置其他偏好、草稿、凭据或用户内容。
- 不改变权限批准/拒绝决定，不扩大工具执行权限，不改 Agent/项目指令。安全提示是否允许“不再询问”是独立产品决策。
- 提供明确作用范围和成功/失败反馈；是否采用确认对话框是本项目设计选择，原版未实测。

### 5. VS Code 扩展导入

- 当前头号玩家设置/快捷键导入范围见 [VS Code 导入说明](VSCODE-IMPORT.md)；它不安装扩展。不得把这部分已完成的导入宣称为完成原版扩展入口。
- 完成扩展导入前，需要独立确定扩展运行机制、兼容范围、来源和安装授权；仅枚举扩展清单不等于导入成功。
- 如先提供兼容性预览，应显式区分“发现”“支持”“不支持”“已安装/安装失败”，未知项保留未知；不自动执行扩展代码，不读取或复制扩展凭据。
- 后续仅用合成 VS Code 配置/扩展清单验证选择、取消、重复项、不支持项和失败回滚；实际支持的扩展还需独立运行验收。
- 现阶段不能根据入口文字规划或声称任意 VS Code 扩展兼容；向导细节与真实导入行为仍需另一轮明确允许执行的隔离验证。
