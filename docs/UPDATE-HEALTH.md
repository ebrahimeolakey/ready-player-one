# 更新后的健康确认与恢复

本功能尚在源码验收阶段；未替换用户已安装的应用。历史发布的安装与启动实测见 [UPDATER-MAC-VALIDATION.md](./UPDATER-MAC-VALIDATION.md)。

## Mac 安装合同

检查官方 GitHub Release、下载完整 ZIP 并核对 SHA256 后，仍需用户点击安装。安装前验证 bundle ID、版本、Mach-O 架构、文件内容摘要、真实安装目录以及目录设备号/inode。

仅当实际旧包与新包的 `Info.plist` 都声明 `RPOUpdateHealthProtocol = 1`、`RPODataCompatibilityEpoch = 1` 时，才启用启动失败自动恢复。缺失/不同/未支持的代际不会推断。旧发布包没有声明，因此第一次升级到此功能时是手动恢复模式：先显示风险与备份路径，用户另行点击“仅安装并保留备份”才安装。

自动路径执行过程：

1. 在本次私有更新缓存完整复制旧 `.app`，检查副本摘要与原包一致，复制自包含 worker；空间、复制或校验失败发生在安装目录变更之前。worker 只依赖 Node 内置模块，使用副本中的 Electron Node 模式，不依赖随后会被移动的安装路径。
2. 私有计划文件以 `0600` 创建；启动参数绑定计划 SHA256。worker 排他锁防止同一事务重复执行。应用读到对应事务就绪日志后写入认证激活记录，才退出；worker 未就绪或未获得激活均不安装。
3. 原进程退出后，再核对两个 bundle 的摘要和目录身份。旧包移动至同目录 `.rpo-backup-<id>.app`，新包移至原路径。只启动此次目标路径中的确切二进制，不使用 LaunchServices 选择另一个已打开实例。
4. 主进程最早消耗并删除一次性健康票据环境变量；Provider/CLI 不继承该票据。启动窗口仅显示验证页面，IPC、Agent 恢复/执行、同步和草稿迁移保持关闭。
5. 通过认证加密存储重读、Hub 连接/状态、主 frame 绑定的随机 bootstrap 标记及实际 React 挂载响应检查后，才发送第一次健康确认。至少观察 10 秒，再检查一次，worker 再核对目标文件。总窗口 120 秒。
6. 确认包含本次 id、确切子进程 PID、版本、目标路径、可执行文件、数据目录、bundle 摘要及协议/代际。127.0.0.1 通道使用一次性令牌、HMAC 挑战、严格 Host/Origin；只有 `process alive` 或窗口对象存在不算通过。
7. worker 将认证的成功回执持久化后才允许解锁工作区。丢失最终网络 ACK 可以读取同一 PID 的签名回执。该提交点之后不再因通信或 worker 退出而自动回滚，防止用户开始工作后被撤换。

## 失败恢复与边界

退出、损坏或超时且尚未确认时，worker 仅终止自己启动的新应用进程组。无法确认整组退出（包括权限拒绝）时，保留现场并记录 `manual-recovery`，不会把未知活进程当成退出。

恢复前再次核对旧备份与新目标的摘要和设备号/inode；目标被后续安装替换、用户改动、备份损坏或目标路径被占用时，不覆盖它们。可以恢复时，新包保存为 `.rpo-failed-<id>.app`，旧包恢复原路径并重新启动，不再携带健康票据。

worker **不复制、不删除、不回滚项目与用户数据**。数据目录禁止与应用/事务缓存重叠；应用更新缓存与备份保留供排查。`journal.json` 记录终态、原路径及备份位置，不含认证令牌。保留完整私有运行时和备份会额外占用磁盘空间；本实现不批量清理其他事务目录。

本协议不是系统掉电的完整事务文件系统：工作进程被系统强杀或机器断电时，可能停在换包中间，排他锁禁止盲目重跑，此时需根据日志及备份人工恢复。也不监控已确认后的任意后续崩溃。

`epoch = 1` 表示维护者承诺当前存储协议可被同代际读取。现有测试证明当前加密 JSON/JSONL 格式与加性字段保留，**不证明两个真实历史版本的全部业务 schema 可互读**。任何不兼容迁移必须提升代际，禁用跨代际自动回滚，并以独立旧版读取新数据的隔离验收支撑未来兼容声明。旧包无声明始终手动恢复。

## Windows / Linux

Windows 保持已校验 NSIS 安装器的显式启动与退出交接；这不是安装成功或启动健康确认，也没有自动启动失败回滚。Windows 上文件锁定、提权与 NSIS 卸载/安装流程不能套用 Mac 目录交换。

Linux AppImage 保持原替换脚本和旧包备份；该平台尚未接入本健康协议。本批不声称 Windows/Linux 的真实升级回滚通过。

## 自动回归与真实验收范围

`node --test tests/updater.test.mjs tests/update-health.test.mjs`：

- 隔离临时目录中实际交换 bundle 目录、启动/终止真实独立 Node 子进程，覆盖健康双阶段、仅进程存活、未挂载/未准备、进程退出、错误 PID 伪造确认。
- 目标后续改动、损坏备份、未知进程退出、启动程序不存在、计划篡改、越界链接、幂等、签名回执和精确路径/代际约束。
- macOS 实际 `PlistBuddy` 读取声明；不支持/缺失声明必须二次明确点击，且保留同一份已校验 staging。
- 当前加密存储协议/加性字段往返。事务测试使用合成 bundle 与协议 fixture，不是完整 Electron/React UI 验收，也没有更换用户 Applications 中的 app。

桌面健康门禁的独立 Electron smoke 与未来两个真实声明版本间的升级，需另记实测证据；不得把 Node fixture 的 `verifyReady:true` 算作 UI/数据真实加载。
