# 中断后的结果确认

执行异常结束、本机恢复未完成执行，或工具许可投递回执丢失时，会话显示「结果待确认」。这是一份可核对的历史记录，不会自动重发原始操作。

展开卡片可查看执行 ID、启动尝试时间、原始用户任务、最近 100 条工具许可投递尝试、对应审批人/时间，以及最近 50 条工具事件。最近完整输出最多保留 8,000 字符；尚未完成的流式片段不进入证据摘要，避免分片或交错输出泄露凭据。原有转录单独保留。工具输入过长时显示截断预览。

「启动尝试」及「许可投递尝试」在调用 Provider 前落入本机加密记录。这些标记无法证明外部操作是否发生：进程可能在保存后、投递前退出，也可能已执行但没有回执。卡片明确区分该标记与实际观测事件，不把审批通过等同于完成。

Editor/Owner 检查实际文件、服务回执或其他证据后，可记录「已确认成功」「已确认失败」「仍不确定」。必须填写证据说明，可包含文件路径或记录链接。每次记录追加版本和操作者，原记录不会覆盖。Viewer/Commenter 可查看，不能决定。人工确认不会提交新任务、重试工具或改变当前执行状态。

同一请求 ID 的重试只写一条历史；旧版本提交被拒绝，要求先查看最新记录。界面也识别来自广播的本次请求记录，避免 RPC 回执丢失后把同一次确认再次提交。未知结果报告使用独立投递通道和原执行领取凭证，因此旧执行已被围栏阻止、或新执行已开始时，仍能补传历史证据，不会恢复旧执行。

## 验证

`tests/outcomes.test.mjs` 使用本地合成计数器：许可实际使文件从 0 变为 1，再故意丢失回执。重启加密执行记录后计数仍为 1，Provider 没有再次启动，许可没有再次投递，Hub 只有一条结果记录。另覆盖报告丢 ACK、跨成员/工作区拒绝、旧执行不复活、版本冲突、重复确认幂等、只追加审计历史、审批证据来源校验、空白输出及交错凭据分片。

macOS Electron 独立合成数据目录已实测：待确认入口→展开证据→填写核对说明→选择成功→保存→显示一条确认历史。没有对真实服务制造副作用或耗尽模型额度；该证据不替代两台实体设备跨互联网验收。

旧版本记录若缺少启动时间或领取凭证，不会编造精确证据。被撤销权限的成员也不能借历史投递绕过当前工作区权限；本机保留投递错误供检查。
