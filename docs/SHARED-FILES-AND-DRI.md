# 项目草稿共享与 DRI 发布

2026-09-29。macOS 0.5.0-beta.6 更新：普通文件夹与项目 PR 目标分离。

## 操作

项目 → 产物 → 共享产物 → 选择自己的来源会话 → 选择文件（可多选）。
只允许项目授权目录内的文件。任务声明的产物自动共享；其他文件明确选择后持续跟踪，不扫描整个电脑。

制作中的原件保留在执行者目录。每 1.2 秒采样，连续两次内容一致才同步。共享版本以加密文件保存于 Hub 的 `artifacts/<versionId>.json.enc`，成员经团队权限检查读取。网络断开或上传失败不会伪装为同步成功。执行者离线后，只要 Hub 在线，已有版本仍可读；本地 Hub 随房主离线而不可访问。

## 文件和预览

- 单文件最大 8 MiB；保留不可变历史版本和 SHA-256。下载校验后还原原始字节，包括文本 BOM 和换行。
- HTML、Markdown 使用禁用脚本的静态沙箱；普通文本显示源文。
- PNG/JPEG/GIF/WebP 查看图片；PDF 使用本地 PDF.js 的兼容构建和随包资源，支持翻页。
- XLSX 提供缓存单元格值预览（最多 10 张表、每表 200 行、100 列）；DOCX/PPTX 提供文字内容预览。不开宏、不计算公式，不承诺完整 Office 排版。OOXML 解压上限 16 MiB。
- 其他文件可共享、保留版本、下载。没有实时多人同文档编辑、跨机器自动合并、整站资源代理或目录自动发现。

## 审批和发布

任务产物只能由任务 DRI 验收；其他共享文件由项目 DRI 审批。执行控制者权限不等于审批权。只能审批当前最新且可读取的版本；审批记录固定版本、内容 hash、审批人和时间。

新文件版本不继承旧版本的批准。上一个已批准版本在新批准取代它前仍可明确选择并发布。

项目负责人先在「PR 目标」选择 GitHub 仓库、合并目标分支和可选目录；成员在自己电脑选择工作文件夹。配置 PR 目标不会初始化本地 Git，也不会改变代码仓库绑定。

DRI 点击「创建 GitHub PR」后，预览账号、仓库公开性、目标分支、文件路径、获批版本和新建分支名，再点「确认创建 PR」。使用本机 `gh` 登录授权；仓库和目标分支需已存在，账号需有写入权限。只把一份获批快照提交到唯一的新分支，然后创建 PR；不直接修改目标分支，不自动合并，不读取未审批的工作目录内容。

发布前及各写入阶段重新检查团队身份、审批、GitHub 账号、仓库 ID/公开性/权限、项目 PR 目标和分支状态。每个外部写入前持久化阶段回执。超时或结果不确定时不会自动重发，检查状态会核对独立分支、内容 SHA、操作标识和对应 PR。仅创建分支或提交而未确认 PR 时，仍标为待核实，需到 GitHub 检查，不伪装为发布成功。记录保存在 DRI 本机。应用之外的 Git/CLI 操作不受此审批流程约束。

## 验证范围

真实 Electron 窗口 + Hub + 本地文件：多选共享，Excel/Word/图片/PDF 预览，下载字节一致，文件修改后自动同步，审批后出现发布按钮、新版重新审批。

Hub 双身份测试：非 DRI 拒绝审批/发布、只读成员可取文件、执行者断线后读取已上传版本、二进制跨 WebSocket 传输。

PR 服务使用模拟 API 验证审批、账号、项目目标、仓库权限与分支变化，以及部分失败、进程重启和不重复发送。beta.6 使用纯合成测试文件完成真实 GitHub 分支、提交和草稿 PR 创建，重复调用未重复写入；测试 PR #1 已关闭、未合并，测试分支已删除。真实 GitHub 验证使用合成审批记录，尚非两台实体 Mac 上真人 DRI 的完整验收。

共享产物阶段回归：455 项测试通过（并发度 2）；加入新手引导和 Agent 管理后，全量 465 项通过（并发度 4）。较早一次并发度 4 的回归中，原有窄屏聊天页测试超时；单独重跑及最终全量重跑均通过。PDF、Excel、Word、图片的桌面验收使用合成文件，验证真实窗口渲染和下载，不调用真实模型。
