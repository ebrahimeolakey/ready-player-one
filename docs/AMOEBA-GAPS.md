# 与 Amoeba 的功能差距

核对日期：2026-09-24。本表以**头号玩家 0.4.2-beta.1 源码与测试**为当前状态，对照 **Amoeba 0.1.38**；0.1.40 增量单列。安装包是否已发布以 README 下载区为准。群聊与 ProjectContext 属于另一批开发，未包含在本次发行源码中。

官方文档没有逐页版本号，下表将其作为功能说明，版本归属优先参考[官方发布日志](https://useamoeba.com/changelog)。核对当日最新日志已到 0.1.40；其 Mac 版本仍等待公证，Mac 下载和更新仍为 0.1.38。不能把最新文档中的每句话未经确认倒推为所有旧版已交付行为。

结论：多人通道、权限、原生运行时、审批、快照、接管、子任务、加密、编辑器和输入恢复已不再是“未做”。主要剩余工作是**具体流程补齐和真实多机验收**，另有用户已明确延后的外部配置。尚不能声称全部功能或所有 UI 状态 1:1。

## 如何阅读状态

- **已实现，待验收**：有可执行代码和针对性测试，部分也有真实 CLI/桌面证据；剩余的是列出的端到端场景，不能等同“未实现”。
- **部分实现**：主流程存在，但明确列出的行为或入口缺失。
- **未实现**：本次在相关源码/接口中未找到对应闭环，不能靠按钮、理论上的 CLI 能力或 mock 测试算完成。
- **外部配置延后**：用户接受先发未签名测试版；证书、OAuth 应用和固定 HTTPS 回调以后补。
- **范围例外**：房主在线、无常驻协调服务；后续本机接力/可选云执行已有设计，尚未部署，不阻塞当前本地版本验收。

[实施记录](IMPLEMENTATION-TRACKER.md)记载 0.4.1 发布时完整回归 **211 项通过**、TypeScript/Vite 构建通过、Mac arm64 打包应用启动及加密草稿恢复。此文是文档/源码审计，没有重新把全部自动化测试或所有硬件流程跑一遍。早期 [VALIDATION](VALIDATION.md) 的 22 项和 [UI-REFERENCE](UI-REFERENCE.md) 的 v0.3 观察属于历史记录，不能覆盖后续实现，也不能当成当前全部 UI 的验收。

## 不应误列为已证实的原版必补功能

- **任意 VS Code 扩展、所有语言/LSP、所有 DAP 调试器**：当前有 JS/TS 语言服务与 Node.js 调试；“完整 IDE”措辞不能证明任意扩展兼容。没有具体官方证据前，它们属于可选扩展方向。
- **跨机器迁移 Provider 的内部 session/登录进程**：已实现的是共享代码/计划/上下文接力和新账号执行；原生 session ID 不能当成可跨账号迁移的凭据。
- **语义 AI、操作系统文件锁、零冲突或端到端加密**：规则提醒、建议锁、Git 合并和静态加密分别是不同能力，不可混称。
- **企业 SAML/SCIM、组织目录、云端执行**：GitHub 团队身份不等于企业 SSO；产品材料未充分证明的能力不自动成为原版必补项。云执行是用户后续选择的方向，另行设计。
- **字符级协同编辑算法**：官网描述共享光标/文件不代表已证实采用 CRDT/OT。当前源码没有远端光标协议，可进一步对照，但不能把某一种算法指定为复刻验收标准。
- **早期运营/FDE 专用模板**：用户后来要求只按 Amoeba 对齐，旧 [PRODUCT-GAPS](PRODUCT-GAPS.md) 的场景建议不是本表待办。

可直接开发的任务与逐项验收动作见 [AMOEBA-ACCEPTANCE](AMOEBA-ACCEPTANCE.md)。
