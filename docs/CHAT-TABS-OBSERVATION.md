## 本项目建议（设计，不是原版实证）

本项目已有 `AgentLane` 与按 lane 管理的 Composer。建议将**单个 lane 的 Agent 对话视图**作为本轮标签对象，复用现有转录、工具审批与输入状态，不将整个多人 session 重命名为一个 chat。

建议稳定目标：

```ts
type ChatTabTarget = {
  connectionKey: string;
  workspaceId: string;
  sessionId: string;
  laneId: string;
};
// 仅改变展示位置与焦点，不调用 Agent 执行接口。
onOpenChat(target: ChatTabTarget): void;
onCloseChat(target: ChatTabTarget): void;
```

名字、Provider、状态从当前 state 派生；不能用可变化的人名/Provider 作为标签身份。连接身份用于本地隔离，不含凭据，不发送给 Provider。

建议在当前 Agent 视图提供明确的“在编辑器中打开聊天”入口，设置项决定默认打开位置。多个聊天标签与文件视图共存；同一目标重复打开只聚焦。Portal 移动同一 lane 容器可保留组件状态，避免重建造成输入丢失。具体标签跨页面恢复策略由本项目明确说明，不能声称与原版完全相同。

## 必须单独验证的行为

- 打开、聚焦、关闭、切换位置均不创建 Provider 会话、不重放历史输入、不调用 `run.stop`。
- 关闭视图不删除已保存或未发送草稿；运行中的 lane 继续由后台管理，重新打开显示同一运行。
- 同一 lane 只有一个有效输入实例；所有发送和审批仍绑定正确 workspace/session/lane。
- 文件编辑器保持挂载或有等价草稿保护，聊天标签不能覆盖未保存文件；空编辑器自动隐藏逻辑需考虑聊天标签。
- 连接改变清除旧视图目标；lane 删除/权限变化后禁止向旧目标发送，不自动替换成另一 lane。
- 用合成 fixture 验证多 lane、重复打开、关闭、正在运行/等待审批、草稿、降权与会话切换。不得把仅有 UI 截图当作运行连续性验收。
