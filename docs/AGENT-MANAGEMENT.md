# Agent 管理与协作：本地开发版

2026-09-27。随 macOS 0.5.0-beta.3 提供；本次不发布 Windows 安装包。

## 本机工作目录与 PR 目标（beta.6）

引导第 2 步默认选择「本地工作文件夹」，例如桌面的 `TEST`。AI 在该目录制作文件，不需要 Git，不继承项目仓库的子目录，也不会自动初始化仓库或切换分支。产物共享和 DRI 审批发布保持不变。

修改项目代码时选择「代码仓库」：界面显示绑定仓库、分支及子目录，校验匹配后才连接；可以选择仓库根目录或恰好对应的项目子目录。取消选择或校验失败不会覆盖已有映射。旧映射仍按原有仓库规则处理，不能静默降为普通文件夹。

目录与用途保存在本机，并随独立 worker 配置导出。更换用途后需重新选择目录，运行中的项目任务或 AI 会话必须先停止。项目侧栏「PR 目标」和引导第 2 步提供仓库选择、合并目标分支及目录配置，由项目 DRI 保存给团队使用。该目标独立于本机目录和项目代码仓库。

## 新手主路径：8 步弹窗

1. 认识项目空间：群聊讨论、任务执行、产物交付。
2. 连接本机工作文件夹。
3. 安装/登录 Codex 或 Claude Code，选择模型。
4. 从角色模板创建第一位独立 AI 搭档。
5. 邀请同事；也可先自己试用。
6. 在群里实际 @ 搭档，发出第一条请求。
7. 创建第一项任务，预填目标和验收示例，提交前可修改。
8. 查看工作中的产物，理解最终负责人（DRI）的审批职责。

随时关闭、继续；步骤保存在 Hub。首次进入团队自动出现一次，项目侧栏可重新打开。向导中的说明是产品文案；真正问 Cindy 时才调用自己的 AI 账号，不伪装模型回复。

## AI 成员面板

- **身份**：头像、名称、职责，选择模板、修改、另存或更新团队模板。
- **运行**：选择本人已连接的电脑、runtime、模型/推理强度；暂停/恢复；新会话保留身份与记忆，旧会话归档。
- **协作**：手动、被 @、参与讨论；选择参与的项目；可明确开启自动接单与执行；每小时轮次上限覆盖自动群聊和自动任务。
- **记忆**：本人维护的长期记忆和独立 Agent 文件夹，模型运行时注入；项目交付物仍在项目文件夹。
- **提醒**：一次或重复跟进，取消、推迟一小时；离线期间保留，在线后处理，不补发一长串错过的重复提醒。
- **工具**：Agent 专属 MCP stdio 服务和环境变量，加密存本机；本轮适配 Codex / Claude Code。MCP 应用仍使用其自己的授权流程。
- **活动**：等待、运行、完成、失败、取消及实际执行会话。

Cindy 的建议在服务端保存为配置草稿。点操作卡后先核对账号、模型、名称和职责，再提交普通权限校验的创建操作；重复提交同一草稿不会重复创建成员。新建的 Cindy 引导会话仅持有人可读；已有共享 Cindy 会话不会被追溯改为私人会话。团队管理员可关闭自动引导，或指定另一位 Agent 的公开角色作为引导职责；新用户仍使用自己的账号和独立引导会话，不占用管理员的账号。

## 从群聊到共同工作

人类消息按 Agent 的参与项目及触发策略进入持久收件箱。由绑定电脑上已登录的本机 worker 领取。每个 Agent 串行自动运行；共享讨论使用独立的项目会话，不恢复私人引导会话。Agent 回复可以向同项目的另一个 Agent 发协作请求；请求由对方自己的电脑执行。直接 consult 最多两层，每轮最多两位，避免无限互相唤醒。

默认自动接单关闭。持有人开启后，模型的任务提案会创建可追踪任务、认领并启动；被其他 Agent 指派的分工也可按此策略接单。任务卡仍打开同一个共享任务会话，每个参与者有自己的执行通道。运行中产物沿用版本同步，DRI 批准特定版本后才能显式发布 GitHub。自动协作不会替代 DRI 审批。

执行请求绑定电脑 ID；服务端拒绝其他电脑领取，领取 nonce 防止重复执行。暂停会停止讨论运行和此 Agent 的进行中任务，取消等待事件。重连不自动重放未知外部操作。

团队内项目仍遵循现有团队访问权限；“参与项目”控制 Agent 的自动投递和任务范围，不等于新建了私密项目 ACL。完整私人频道不是本轮交付。

## 电脑服务

“成员与 Agent → 电脑与团队设置”显示电脑在线状态、运行时和故障。

- 开启“关闭窗口后继续运行”：关窗口隐藏应用，本机服务继续；退出应用或电脑关机则停止。
- “配置独立执行服务”：导出仅本人可读的连接文件和 macOS `.command` 启动器。双击启动器可独立于 UI 运行，终端 Ctrl+C 停止。配置包含本人登录凭据和所选 Agent 工具配置，不可发送给同事。
- 源码方式：`node core/agent-worker.mjs --config /absolute/path/rpo-computer.json`。
- 独立 worker 本轮支持 Codex / Claude Code，持久化执行与同步产物。当前没有安装 login item / launchd 自动启动服务，也不会提供云端电脑。
- Hub 是另一项服务，仍需在线；如果 Hub 就在桌面应用进程里，退出应用后独立 worker 也无法继续协作。使用独立或远程 Hub 才能脱离桌面房主。

## 自行运行的外接 Agent

成员面板 → 工具 → 接入自行运行的 Agent：

1. 为此身份生成有效期 5 分钟的本机接入码。
2. 在本机终端运行界面给出的配对命令，配置文件仅本人可读。
3. 将生成的 MCP 配置加入自己运行的 Claude Code 或其他兼容 MCP 的宿主。
4. 外部 Agent 调用 `rpo_next` 领取此身份的工作，处理后用 `rpo_reply` 回传；`rpo_context` 读当前项目上下文，`rpo_contribute` 请求共享任务分工。

授权仅绑定一位 Agent，不能代理通用应用 RPC，不向外部运行时暴露 Hub 人类登录令牌。可即时撤销、恢复内置托管。界面区分“已授权等待连接”与“最近有通信”。桥只监听本机，桌面应用需在线；跨电脑成员在各自电脑配对。它不是导入任意 CLI 历史会话的扫描器，也不是 Raft 官方协议兼容实现。外部宿主负责自身工具权限；应用无法强制它的文件系统沙箱。断开时正在运行的外部模型需在其宿主停止；已撤销连接无法继续回传。

## 可修改角色示例

模板文件：`agent-role-templates.json`。可直接在应用中选择同名内置模板、修改职责并另存。

| 模板 | 工作职责 | 推荐初始权限 |
| --- | --- | --- |
| 项目协调 | 提炼目标，拆任务、明确 DRI，跟进阻塞 | 被 @ 时回应，自动接单关闭 |
| 执行搭档 | 在任务内制作初稿，持续共享版本，请求复核 | 被 @ 时回应；熟悉后再开自动接单 |
| 复核搭档 | 按验收条件核对内容/来源，给修改建议 | 被 @ 时回应，最终审批交给人 |

例如把“复核搭档”改为“活动方案复核”，职责写成：**检查时间、预算、人员分工和风险是否齐全；标出缺项与来源；请执行搭档修正；不替负责人批准或发布。** 修改的是角色配置，身份、账号和历史仍保留。

## 验证记录与限制

- 真实打包应用 + 本机真实 Codex：项目协调 → consult 复核搭档 → 两位独立 Agent 发回群聊；原任务状态不变。见 [本版验证记录](evidence/agent-onboarding-0.5.0-beta.3.json)。
- 实际 Electron/React/Hub/子进程协议测试：8 步引导、Cindy 草稿到 Agent、多个持有人共享任务、产物版本、权限。
- 独立 worker 测试启动真实 Node/CLI 子进程，重启后不重复执行。该测试的模型响应是明确的协议 fixture。
- 外接桥测试真实 HTTP 配对、单成员能力范围、撤销、真实 Hub 运行输出；尚未完成每种第三方 MCP 宿主的实机互操作验证。
- 真实模型验证用一台 Mac、两个 Codex 会话；本机 Claude Code 未登录。多成员权限与协作已在独立客户端/执行进程验证，尚未做两台物理电脑的互联网验收。
- 不宣称具备 Raft 的所有 SaaS 应用授权、私密频道、云端运行时或官方托管 Agent。
